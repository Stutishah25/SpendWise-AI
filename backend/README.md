# SpendWise AI: database layer (Phase 1)

PostgreSQL 16 → SQLAlchemy 2.x models → Alembic migration → seed + tests. No API, frontend or finance engine yet.

## Setup
```bash
cp ../.env.example ../.env            # edit the password
docker compose --env-file ../.env -f ../docker-compose.yml up -d db     # or use any PostgreSQL 15+ server
python -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
export DATABASE_URL=postgresql+psycopg://spendwise:<password>@localhost:5432/spendwise
alembic upgrade head                  # creates extensions, enums, 31 tables, triggers, view, currency seed
alembic check                         # must print "No new upgrade operations detected."
```
Rollback: `alembic downgrade base` (extensions are intentionally left installed).
Offline SQL: `alembic upgrade head --sql > schema.sql`.

## Seed demo data (synthetic, login-disabled accounts)
```bash
python -m scripts.seed_dev            # idempotent
python -m scripts.seed_dev --reset    # deletes the two demo users (full cascade) and re-seeds
```

## Tests (build a throw-away DB from the migration for every session)
```bash
export TEST_ADMIN_URL=postgresql+psycopg://spendwise:<password>@localhost:5432/postgres   # role needs CREATEDB
pytest -q
```

## Layout
- `app/models/`  one module per domain (user, category, transaction, goal, loan, investment, financial_snapshot, scenario, ai_analysis, notification, audit) + `enums.py`, `base.py`
- `alembic/versions/0001_initial_schema.py`  tables (autogenerated) + frozen SQL for extensions/enums/functions/triggers/view
- `docs/spendwise_schema.sql`  reviewed reference DDL (the migration is diffed against it in validation)
- `scripts/seed_dev.py`, `tests/db/`

## Conventions that matter
- Writes always set `user_id` from the authenticated principal; composite FKs `(id, user_id)` make cross-user links impossible.
- "Protective" FKs are DEFERRABLE INITIALLY DEFERRED: an in-use category/snapshot/run is rejected at COMMIT, so catch `IntegrityError` around `commit()`.
- Relationships between composite-FK tables are `viewonly=True`; create rows by setting FK columns explicitly.
- Runtime DB role: no table ownership, no BYPASSRLS; INSERT+SELECT only on `audit_log`.
